# 环境搭建（Windows + RTX 4060）

## 0. 前提

- Windows 10/11 x64
- NVIDIA 驱动已安装（`nvidia-smi` 能跑）
- 不需要装 CUDA Toolkit（预编译包自带运行库）

## 1. 下载 llama.cpp 预编译包

打开 <https://github.com/ggml-org/llama.cpp/releases/tag/b11960>，下载两个包：

| 文件 | 大小 | 说明 |
|---|---|---|
| `llama-b11960-bin-win-cuda-12.4-x64.zip` | ~280 MB | 主程序 |
| `cudart-llama-bin-win-cuda-12.4-x64.zip` | ~390 MB | CUDA 运行库 |

> 如果驱动版本很新，也可以选 CUDA 13.4 的那两个包，二选一，不要混用。

## 2. 解压

把两个 zip **解压到同一个目录**，例如：

```
D:\tools\llamacpp\
├── llama-cli.exe
├── llama-bench.exe
├── llama-server.exe
├── ggml-cuda.dll
├── cudart64_12.dll
└── ...
```

解压后在该目录打开 PowerShell，执行：

```powershell
.\llama-cli.exe --version
```

能打印版本号就说明可执行文件正常。

## 3. 下载模型

用 ModelScope（国内快）下载 Qwen2.5-1.5B 的 GGUF：

<https://modelscope.cn/models/Qwen/Qwen2.5-1.5B-Instruct-GGUF>

进「模型文件」页，下载三个量化版本（用于对比）：

- `qwen2.5-1.5b-instruct-q4_k_m.gguf`（约 1.0 GB）
- `qwen2.5-1.5b-instruct-q5_k_m.gguf`（约 1.2 GB）
- `qwen2.5-1.5b-instruct-q8_0.gguf`（约 1.8 GB）

放到 `D:\tools\models\` 下。

## 4. 跑通第一个对话

```powershell
cd D:\tools\llamacpp
.\llama-cli.exe -m D:\tools\models\qwen2.5-1.5b-instruct-q4_k_m.gguf -ngl 99 -p "用一句话介绍你自己" -n 64
```

- `-ngl 99`：把所有层卸载到 GPU（4060 跑 1.5B 完全够）
- `-n 64`：最多生成 64 个 token

看到输出且速度正常（几十 tokens/s）就说明 GPU 生效了。

## 5. 跑 benchmark

```powershell
.\llama-bench.exe -m D:\tools\models\qwen2.5-1.5b-instruct-q4_k_m.gguf -p 512 -n 128 -ngl 99
```

输出形如：

```
| model | size | params | backend | ngl | test | t/s |
| qwen2.5 1.5B Q4_K_M | 1.0 GiB | 1.54 B | CUDA | 99 | pp512 | 1234.56 ± 12.34 |
| qwen2.5 1.5B Q4_K_M | 1.0 GiB | 1.54 B | CUDA | 99 | tg128 | 56.78 ± 0.45 |
```

记录 `pp`（prompt 处理）和 `tg`（文本生成）两个 t/s。

## 6. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `ggml-cuda.dll 找不到` | cudart 包没解压到同一目录 | 两个 zip 解压到同一文件夹 |
| 速度只有几 tokens/s | 没走 GPU | 确认 `-ngl 99`，并看启动日志里的 `CUDA0` |
| 显存不足 | 模型太大 / 上下文太长 | 降量化等级、减小 `-c` |
| `nvidia-smi` 报错 | 驱动问题 | 先修驱动，再谈 CUDA |

## 6.5 实际采用的路线（国内网络，2026-11-03）

GitHub 直连不通、多数加速镜像也不稳定，最终改成 **从国内镜像拉源码 + 本地编译**：

```powershell
# 1. 从 GitCode 镜像克隆（约 16 秒）
git clone --depth 1 https://gitcode.com/gh_mirrors/ll/llama.cpp D:\tools\llama.cpp-src

# 2. 用 MinGW gcc + Ninja 构建（约 6 分钟）
cd D:\tools\llama.cpp-src
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release `
      -DGGML_CUDA=OFF -DLLAMA_CURL=OFF `
      -DCMAKE_CXX_FLAGS="-D_WIN32_WINNT=0x0A00" `
      -DCMAKE_C_FLAGS="-D_WIN32_WINNT=0x0A00"
cmake --build build -j 16
```

产物在 `D:\tools\llama.cpp-src\build\bin\`。

**踩到的坑**：不定义 `_WIN32_WINNT=0x0A00` 时，MinGW 编译 `vendor/cpp-httplib/httplib.h`
会报 `#error "cpp-httplib doesn't support Windows 8 or lower"`，`httplib.cpp` 还会报
`'::CreateFile2' has not been declared`。这是 MinGW 默认 `_WIN32_WINNT` 版本偏低导致的。

模型从 ModelScope 下载，实测约 12 MB/s：

```powershell
curl -L -o D:\tools\models\qwen2.5-1.5b-instruct-q4_k_m.gguf `
  https://modelscope.cn/models/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/master/qwen2.5-1.5b-instruct-q4_k_m.gguf
```

## 6.6 自行编译 CUDA 版（GPU 后端）

预编译包下不动（GitHub 不可达），改成自编译。依赖两样东西：

| 依赖 | 版本 | 大小 | 来源 |
|---|---|---|---|
| VS Build Tools（MSVC） | 17.14.44 / MSVC 14.44 | ~3 GB | winget / 微软 CDN |
| CUDA Toolkit | 12.4 | 3 GB | NVIDIA 中国 CDN |

### 安装 CUDA（只装必需组件）

```powershell
cuda_12.4.0_551.61_windows.exe -s nvcc_12.4 cudart_12.4 cublas_12.4 cublas_dev_12.4
```

> 注意：`ggml-cuda` 链接 `CUDA::cublas`，所以 **cublas 必须装**，只装 nvcc + cudart 会在
> 生成阶段报 `Target "ggml-cuda" links to: CUDA::cublas`。

### 编译

```powershell
# 载入 MSVC 环境变量，再配置
cmd /c '"C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat" && ^
  cmake -S . -B build-cuda -G Ninja -DCMAKE_BUILD_TYPE=Release ^
        -DGGML_CUDA=ON -DLLAMA_CURL=OFF -DCMAKE_CUDA_ARCHITECTURES=89 && ^
  cmake --build build-cuda -j 16'
```

两个关键点：

1. **不能用 Visual Studio 生成器**：它需要 CUDA 的 `visual_studio_integration` 组件，
   没装就会报 `No CUDA toolset found`。用 **Ninja + vcvars64.bat** 绕开。
2. `-DCMAKE_CUDA_ARCHITECTURES=89` 只编译 RTX 4060（Ada，compute capability 8.9）这一代，
   编译时间从几十分钟降到约 12 分钟。换显卡要改这个数。

### 踩坑记录

| 报错 | 原因 | 解决 |
|---|---|---|
| `Could not find nvcc` | CMake 没搜到 CUDA | `-DCUDAToolkit_ROOT="C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.4"` |
| `No CUDA toolset found` | 缺 VS 集成组件 | 改用 Ninja 生成器 + vcvars64 |
| `links to: CUDA::cublas` | 只装了 nvcc/cudart | 补装 cublas + cublas_dev |

### 生成物

新版 llama.cpp 把实现拆进了 DLL，`exe` 只是几 KB 的启动器：

```
build-cuda/bin/
├── llama-bench.exe      （10 KB，启动器）
├── llama-cli.exe
├── ggml-cuda.dll        （200 MB，CUDA kernel 都在这里）
├── llama.dll / ggml-cpu.dll / llama-common.dll
```

运行时需要 CUDA 的 DLL（`cublas64_12.dll` 等），所以要把
`C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.4\bin` 加进 PATH。
